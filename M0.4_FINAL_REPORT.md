# M0.4 Final Report — Development Tooling, CI, and the `verify` Gate

**Status:** Complete
**Date:** 2026-08-08
**Branch:** `develop`
**Scope:** M0.4 ships the single authoritative verification gate (`bun run verify`), wire-level tests on both sides, and a CI workflow that runs exactly that gate. It does **not** start Phase 1 work.

---

## 1. Summary

M0.4 turned "verification happens locally and ad hoc" into a single, CI-enforced,
fail-fast command that any developer (or agent) runs from any directory:

```
bun run verify
```

Nine gates run in a fixed order; the first failure stops the run with the
failing step's exit code. CI (`ci.yml`) runs exactly this one script, so a red
pipeline reproduces locally with a single command — no CI/local drift.

Baseline for comparison: the repo previously had **no working format gate**
(`prettier --check src/` failed on 75 files), **no clippy gate with
`-D warnings`** (9 warnings), and **no test coverage for the IPC contract layer
or the command surface**. All of that is resolved.

## 2. What changed

### 2.1 The `verify` gate

- `scripts/verify.ts` — new orchestrator. Nine steps, fail-fast, cwd-independent
  (every cargo call passes `--manifest-path ./src-tauri/Cargo.toml`; the script
  resolves its own root via `import.meta.dir`).
- `package.json` — added `verify` plus the missing cargo scripts
  (`cargo:fmt:check`, `cargo:clippy`); kept `cargo:check`/`cargo:test`/`cargo:build`.
  The existing `gate` script is now documented as a legacy alias.

| # | Step | Command | Guards |
|---|------|---------|--------|
| 1 | Frontend formatting | `prettier --check src/` | format gate |
| 2 | Backend formatting | `cargo fmt --check` | format gate |
| 3 | Frontend lint | `eslint src/` | lint gate |
| 4 | Frontend types | `svelte-kit sync && svelte-check` | type gate |
| 5 | Backend lint | `cargo clippy --all-targets --all-features -D warnings` | lint gate |
| 6 | Backend types | `cargo check` | type gate |
| 7 | Frontend tests | `vitest run` | test gate |
| 8 | Frontend build | `vite build` | build gate |
| 9 | Backend tests | `cargo test` | test gate |

### 2.2 Warning cleanup (Rust)

All `cargo check` / `cargo clippy -D warnings` warnings are resolved:

- `utils/errors.rs` — the `AppError` enum and constructor block carry narrow,
  documented `#[allow(dead_code)]`: the closed wire-code set (ADR-0002) is
  intentional foundation whose variants are constructed as their owning command
  domains ship.
- `utils/logger.rs` — module-level documented `#![allow(dead_code)]`: the
  tracing facade is consumed by the backend wiring milestone.
- `utils/errors.rs:262` — genuine fix: `std::io::Error::new(ErrorKind::Other, …)`
  → `std::io::Error::other("disk full")` (clippy `io_other_error`).

### 2.3 Tests (minimum production-ready suite)

**Frontend — 61 tests across 8 files** (`tests/frontend/`, node env, `$lib` +
`lucide-svelte` stubs):

- `contracts.test.ts` — COMMANDS registry uniqueness/snake_case, `defineCommand`
  duplicate rejection, `SettingsSchema` parse/accept/reject.
- `events.test.ts` — EVENTS naming contract (`dex.<domain>.<event>`), canonical
  payload acceptance, malformed payload rejection.
- `ipc-error.test.ts` — `IpcError.fromUnknown` maps the structured AppError
  envelope to typed codes and transport failures to `"unknown"`.
- `utils.test.ts` — `format*`, `timeAgo`/`formatTime`/`formatDate` buckets and
  invalid-input guards.
- `helpers.test.ts` — `workspaceLabel` / `resolveWorkspace` (longest-prefix).
- `storage.test.ts` — namespaced round-trip, corruption → null, throwing backend
  survival.
- `theme-store.test.ts` — default boot, apply/DOM sync, toggle wrap, reset,
  persisted restore (fresh module via `vi.resetModules`).
- `navigation-config.test.ts` — pre-existing; kept.

The throwaway `scratch-probe.test.ts` was removed (its two assertions are
covered by real tests now).

**Backend — 56 Rust tests** (added 7: `greet` ×3, `ProviderError` Display ×4):
- `commands/core.rs` — `greet` welcomes by name, handles empty names, returns
  typed output.
- `providers/error.rs` — Display for registration conflicts, not-found,
  structural and reasoned variants.
- 49 pre-existing tests (network/process providers, capability, migrations,
  `AppError`) all still pass.

### 2.4 CI

- `.github/workflows/ci.yml` rewritten to a **single `verify` job**: checkout →
  Tauri system deps → Bun 1.3.14 → Rust stable (rustfmt+clippy) → cargo cache →
  `bun install --frozen-lockfile` → `bun run verify`. It runs exactly the gate
  and nothing else. `release.yml` was left untouched (M0.4 ships no release
  pipeline).

### 2.5 Docs

- `AGENTS.md` — Commands section now documents `bun run verify` as the
  authoritative gate; the stale "Live vs. placeholder" claims (no CI, empty
  workflows, inert providers/database, `greet.ts` client) were corrected to the
  verified reality; Verification Order section rewritten to the nine gates.
- `docs/40-engineering/CI.md` — "Current state" corrected (CI is live), pipeline
  diagram and stage details now describe the shipped `verify` gate.

### 2.6 Incidental fixes (uncommitted work from a prior UI slice)

The svelte-check gate surfaced 21 pre-existing type errors in uncommitted UI
work (`ViewPlaceholder` + new route stubs):

- `ViewPlaceholder.svelte` — `icon` prop retyped from Svelte 5's
  `Component<{ class?: string }>` to `typeof import("lucide-svelte").House`
  (the codebase's existing convention) because lucide-svelte v1.0.1 exports
  class components.
- `Badge.svelte` — added the `outline` variant that `ViewPlaceholder` uses.

These are required for the type gate to pass; they are additive and do not
change UI behavior.

## 3. Formatting baseline

The frontend tree was **not** Prettier-formatted before M0.4 (`format:check`
failed on 75 files). M0.4 ran `prettier --write src/` once, normalizing the
tree to the committed `.prettierrc` (79 files touched, formatting-only). The
format gate now passes and will keep future diffs formatted from the start.
`cargo fmt` already passed; the untracked `src-tauri/rustfmt.toml` pins stock
rustfmt rules explicitly.

## 6. What was deliberately not done

- **No Phase 1 work** (no new command handlers, providers, or features).
- **No release pipeline** (`release.yml` untouched).
- **No `bun run tauri:dev` in CI** — it needs a real compositor (ADR-0004) and
  stays a manual desktop gate.
- **No new dependencies** — the gate reuses the already-installed toolchain
  (prettier, eslint, vitest, svelte-check, cargo fmt/clippy).
