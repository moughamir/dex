# M1.1 Final Report — Window: Transparent, Fullscreen, Multi-Monitor, DPI-Aware

**Status:** Complete — **READY FOR REVIEW** (native/manual verification performed)
**Date:** 2026-08-08
**Branch:** `agent/m1.1-window` (commit `dc51278`, on top of `019e55f`)
**Scope:** M1.1 replaces the fake startup delays with a real, resilient handshake and ships an event-driven window/monitor/DPI layer behind the single Tauri import boundary. No new capabilities, no UI redesign, no Phase 2+ work.

---

## 1. Summary

The splashscreen → main-window boot sequence previously contained **fake boot-time work** that violated the startup budget: a hardcoded 2s sleep in the Rust backend lane plus 1.5s + 1s timers in the splashscreen frontend. M1.1 removes all artificial delay and makes readiness real:

- **Backend** completes its half of the handshake immediately (today it is synchronous inside `.setup`; the spawned lane is the documented seam for future async backend init).
- **Frontend** signals completion after its first painted frame (double-`requestAnimationFrame`) via the existing `set_complete` IPC contract.
- A pure `startup_gate(frontend, backend, shown)` predicate + `shown` flag makes the transition **fire exactly once**, under the mutex, with the same window ops as before.
- A **10s failure fallback** force-shows the main window with a warning if the handshake stalls — the user is never stranded on a hidden main window.

Alongside the handshake, M1.1 adds the **window store** (`core/stores/window.svelte.ts`): logical size, DPI scale factor, current monitor, fullscreen/focus state, and readiness — driven entirely by native window events (resize/move/scale/focus), **no polling**. Browser-dev (non-Tauri) falls back to browser globals without subscriptions.

**Capability audit correction:** the plan initially assumed `core:window:default` had to be added for window read APIs. Verified against the tauri-2.11.5 build script that `core:default` **already bundles** `core:window:default` (scale_factor, inner/outer_size, monitors, theme, …) — so **no capability change was needed**, keeping the "no unnecessary capabilities" constraint. The splashscreen's `set_complete` invoke is ACL-exempt (no app ACL manifest, local origin) — confirmed at runtime.

## 4. Preserved functionality

- **ADR-0002**: single `generate_handler!`, commands take one serde struct arg, snake_case wire; `set_complete` wire protocol unchanged (`task: "frontend" | "backend"`); the `COMMANDS` registry contract for `set_complete` unchanged.
- **ADR-0004**: transparency contract intact — no full-window opaque fill introduced.
- **ADR-0005**: CSP untouched (still strict; no dev relaxation shipped).
- `greet` command and its tests unchanged. SQLite init unchanged (synchronous in `.setup`).
- Splashscreen and HUD **markup/design untouched** (zero visual change; readiness timing only).
- **No new dependencies** (Rust or TS).

## 7. Blockers / limitations

- **Multi-monitor and live DPI-scale change were not natively exercisable**: the environment has a single monitor (eDP-1) at scale 1.00. Both event paths are unit-tested; runtime validation needs a multi-monitor or scale-switching session.
- Splashscreen window reports 532×392 in `hyprctl` vs 420×280 in config — pre-existing GTK/window extent behavior, cosmetic, unchanged by M1.1.
